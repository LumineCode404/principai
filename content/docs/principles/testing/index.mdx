---
title: Testing
description: Evidence that software works, and keeps working — suite shape, behavior over implementation, flaky tests, properties, doubles, and the definition of legacy code.
---

Testing is not verification theater — it is evidence, and evidence has an economics. Every test buys confidence at a price in runtime, maintenance, and attention. The principles in this category are about paying that price deliberately: shaping the suite so feedback arrives before it is expensive, asserting behavior so refactors stay safe, quarantining the tests whose randomness destroys trust, and recognizing that code without tests is not old code — it is unchangeable code.
