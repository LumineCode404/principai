Jangan pernah menulis secret ke dalam source file, template konfigurasi, commit message, ticket, chat log, atau output log — bukan juga yang sementara, bukan juga di repository privat. Selalu baca secret dari vault atau environment injection saat runtime, dan lakukan rotasi segera jika sebuah secret pernah menyentuh repo. Jika menemukan secret di kode, di paste, atau di log, berhenti dan laporkan ke manusia beserta lokasi persisnya.

<Severity level="critical" />

## Definisi

Secret adalah credential apa pun yang pengungkapannya menembus security boundary: API key, token, password, private key, connection string. Kode beserta history-nya adalah media broadcast — secret yang sekali di-commit tersalin ke setiap clone, CI log, dan archive, dan menulis ulang history tidak membatalkan kebocorannya. Hygiene berarti secret hanya ada di vault dan runtime injection, di-scope dan dirotasi, serta diperlakukan sebagai compromised sejak ia menyentuh apa pun yang bisa dibaca pihak lain.

## Kapan pakai

- Menulis skrip, service, atau CI job apa pun yang melakukan autentikasi ke sesuatu.
- Commit konfigurasi, infrastructure code, atau container image — lokasi kebocoran yang klasik.
- Debugging dan logging: saat mencetak request header atau environment.
- Menyerahkan credentials kepada agent atau automation untuk bekerja atas nama pemiliknya.

## Kapan TIDAK pakai

- Public key dan identifier lain yang memang dirancang untuk dibagikan — salah label sebagai secret memunculkan alert fatigue, dan itu menyembunyikan yang sungguhan.
- Test fixture dengan nilai palsu secara struktural yang ditolak oleh sistem sungguhan — contoh key yang jelas-jelas invalid itu aman dan berguna.
- Secret terenkripsi yang di-commit ke repo tempat decryption key di-inject oleh CI dari vault — praktik yang diterima di sebagian tim, hanya bisa dibela selama key itu benar-benar tidak pernah masuk git.

## Anti-pattern

- Connection string lengkap dengan password-nya yang di-commit di example env file — file contoh selalu berakhir mendapat nilai asli yang ditempelkan ke dalamnya.
- Token yang ditempel di komentar ticket "cuma untuk sprint ini".
- Deploy key yang dibakar ke dalam base image "karena build terus gagal".
- Mencatat request header dan environment secara penuh di setiap jalur error.
- Berencana mencabut key yang bocor "nanti minggu ini" alih-alih sekarang.
- Memperlakukan repo privat sebagai tempat aman: repo privat tetap di-clone, di-mirror, dan diingat oleh mantan karyawan.

## Contoh kode

Salah — secret hidup di dalam repo:

```bash
# File .env pernah di-commit "sementara" saat kebakaran deploy:
#   DATABASE_URL=postgres://svc:realpassword@prod-db.internal:5432/billing
# Satu push kemudian: setiap clone, CI log, dan mirror repo memegangnya selamanya.
git rm .env && git commit -m "remove env"   # sia-sia — history masih menyimpannya
```

Benar — repo hanya mereferensikan nama; runtime menyediakan nilai:

```bash
# Repo hanya berisi referensi; vault atau CI meng-inject nilai aslinya.
./deploy.sh                      # membaca DATABASE_URL dari environment

# Defense in depth di sekeliling secret:
# - pre-commit secrets scanner: commit gagal SEBELUM history ada
# - vault menerbitkan credentials DB berumur pendek per deploy, bukan per kuartal
# - jika kebocoran dicurigai: rotasi DULU, baru selidiki bagaimana bocornya
```

## Penegakan teknis

<Enforcement>
Hygiene hanya bertahan sebagai tooling:

- **Secret scanning pre-commit dan server-side** di setiap push — termasuk pada penulisan ulang history, yang itu sendiri adalah red flag yang layak diberi alert.
- **Vault plus credentials berumur pendek**: secret diterbitkan per job per run (federasi OIDC ke role cloud alih-alih key berumur panjang), sehingga token yang bocor kedaluwarsa dalam hitungan menit.
- **Masking dan scoping di CI**: secret di-mask di log dan tidak pernah terekspos ke pull request dari fork.
- **Runbook rotasi yang sudah dilatih**: mencabut dan merotasi satu kelas credential dari ujung ke ujung, dilatih sebelum dibutuhkan.
- **Yang mencegah vs. yang mendeteksi**: credentials federated per run mencegah kebocoran berdampak — barang yang bocor kedaluwarsa sebelum ada yang memakainya; scanner mendeteksi kebocoran setelah kejadian. Deteksi memberi tahu bahwa pencegahan tidak sempurna; jangan ship yang pertama tanpa merencanakan yang kedua.
</Enforcement>

## Kasus nyata

<RealCase>
Skenario (ilustratif): seorang engineer me-commit access token yang berfungsi ke sebuah repository — di dalam contoh kode, file config, atau perbaikan larut malam — dan scraper otomatis menemukannya dalam hitungan menit hingga hari. Karena history git efektif append-only, menghapus file tetap meninggalkan token di setiap clone dan archive yang sudah ada; satu-satunya remediasi nyata adalah pencabutan dan rotasi, di bawah tekanan waktu, sementara penyerang sudah memegang credential yang valid. Sebuah peristiwa dunia nyata yang serupa — token npm hasil curian yang dipakai pada 2018 untuk mempublish versi berbahaya dari sebuah package resmi — perlu diverifikasi terhadap sumber primer sebelum dikutip lebih lanjut (verification: perlu). Pelajarannya tetap sama: perlakukan secret apa pun yang pernah menyentuh repo sebagai compromised, dan buat rotasi begitu rutin sampai membosankan. Tidak ada URL yang dikutip karena kasus ini ilustratif, bukan insiden terspesifikasi yang terverifikasi.
</RealCase>

## Tensi dan trade-off

- **Hygiene vs. KISS**: pemasangan vault, scope, dan rotasi menambah kompleksitas setup yang nyata; versi minimal yang membosankan — environment injection dari vault — mengalahkan versi rumit yang tidak dipelihara siapa pun.
- **Secret vs. Observability-First**: debugging ingin nilai credential dan header yang gagal secara persis; mask secara default dan buka mask hanya melalui jalur yang terkontrol dan ter-audit.
- **Rotasi agresif vs. graceful degradation**: credentials yang kedaluwarsa di bawah service yang sedang berjalan bisa menjatuhkannya di tengah jalan; rotasi butuh overlap window atau live reload, dan rotasi yang gagal harus gagal secara keras, bukan secara senyap.

## Prinsip terkait

- [Least Authority](/id/docs/principles/security/least-authority) — credential yang bocor namun scoped dan berumur pendek adalah luka kecil, bukan amputasi.
- [Secure by Default](/id/docs/principles/security/secure-by-default) — tool yang meminta secret hanya saat runtime, tidak pernah di file.
- [Supply Chain Vetting](/id/docs/principles/security/supply-chain-vetting) — token CI yang bocor persis bahan bakar publish package berbahaya.
- [Fail-Safe Defaults](/id/docs/principles/security/fail-safe-defaults) — saat secret hilang, gagal tertutup alih-alih jatuh kembali ke yang ter-commit.
- [Observability First](/id/docs/principles/reliability/observability-first) — log yang cukup kaya untuk debugging, cukup buta untuk disimpan.
- [Append-Only Logs](/id/docs/principles/data/append-only-logs) — mengapa history tidak pernah melupakan, dan mengapa rotasi adalah satu-satunya perbaikan yang nyata.
