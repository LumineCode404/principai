<AIInstruction>
Ship konfigurasi aman sebagai default out-of-the-box dan wajibkan opt-in eksplisit untuk apa pun yang berisiko. Jangan pernah mengaktifkan fitur yang kuat — remote code execution, dynamic lookup, admin interface, debug endpoint — hanya karena nyaman untuk demo. Jika tidak bisa menyebutkan default aman untuk sebuah fitur, berhenti dan tanyakan ke manusia sebelum men-ship-nya.
</AIInstruction>

<Severity level="important" />

## Definisi

Apa pun yang bawaannya aktif ketika sebuah library, framework, atau service di-ship adalah apa yang akan dijalankan sebagian besar instalasi selamanya. Secure by default berarti hasil install segar tanpa modifikasi adalah versi yang sudah di-hardening: enkripsi menyala, fitur berbahaya mati, debug interface tak terjangkau, tanpa default credentials. Segala hal yang melemahkan postur keamanan mensyaratkan opt-in eksplisit dan terdokumentasi — default adalah keputusan yang diambil atas nama setiap user yang tidak akan pernah membaca dokumentasinya.

## Kapan pakai

- Library dan framework yang didistribusikan ke orang-orang yang tak akan pernah ditemui atau di-audit.
- Template infrastructure dan base image yang menciptakan lingkungan yang diwarisi pihak lain.
- Apa pun dengan mode demo — config demo punya kebiasaan menjadi config production.
- Client SDK yang pengaturan default-nya menyebar senyap ke ribuan aplikasi.

## Kapan TIDAK pakai

- Tool internal sekali-pakai dengan threat model tertulis yang secara eksplisit menerima risikonya.
- Contoh pembelajaran yang tujuan utamanya memang mendemonstrasikan mekanisme yang tidak aman — berlabel jelas, tidak pernah menghadap internet.
- Ketika default paling aman membuat produk tak terpakai bagi sebagian besar user: pilih default terkuat yang tetap berfungsi out-of-the-box, lalu ekspos switch hardening untuk sisanya.

## Anti-pattern

- Library logging yang menginterpretasikan dan men-fetch URL yang ditemukan di dalam teks log.
- Admin dashboard yang terikat ke semua interface dengan password default.
- Verifikasi TLS dimatikan dalam contoh kode yang semua orang salin ke production.
- Debug mode yang digerakkan oleh environment variable yang juga diset oleh production.
- "Hardening guide" yang ditawarkan sebagai pengganti default yang aman — dokumentasi bukan kontrol.

## Contoh kode

Salah — fitur yang kuat menyala kecuali tahu cara mematikannya:

```javascript
// Default library: string apa pun yang masuk ke logger bisa memicu remote lookup.
const logger = createLogger({ app: "billing" });
// "messageLookup" default-nya true — nyaman untuk demo, katastrofik di prod

logger.warn(`Payment failed for ${userInput}`);
// userInput datang dari sebuah field request; logger men-fetch apa yang ditemukannya di sana
```

Benar — default inert, opt-in eksplisit dengan scope:

```javascript
// Default-nya inert: teks log adalah data, tidak pernah dieksekusi atau di-fetch.
const logger = createLogger({ app: "billing" });
logger.warn(`Payment failed for ${userInput}`);   // selalu sekadar teks

// Fiturnya tetap ada — untuk orang yang menyebut namanya secara eksplisit:
// const logger = createLogger({
//   app: "billing",
//   messageLookup: { enabled: true, allowHosts: ["metrics.internal"] },
// });
```

## Penegakan teknis

<Enforcement>
Default harus ditegakkan di tempat yang tidak bisa dilewati user:

- **Base image dan template yang ter-hardening**: image se-organisasi dengan debug mati, tanpa default credentials, patch terkini — tim mewarisi keamanan tanpa harus berbuat apa pun.
- **Configuration linting di CI**: gagalkan build pada flag yang diketahui tidak aman — verifikasi TLS mati, debug mode di deploy artifact, wildcard network bind, password default.
- **Test perilaku default**: test fresh-install yang menegaskan fitur berbahaya mati dan fitur aman menyala — default adalah perilaku, jadi test-lah seperti perilaku.
- **Yang mencegah vs. yang mendeteksi**: men-ship default yang aman mencegah misconfiguration bagi mayoritas senyap yang tak pernah mengonfigurasi apa pun; lint dan audit mendeteksi minoritas yang memilih keluar — pelihara keduanya, keduanya melindungi orang yang berbeda.
</Enforcement>

## Kasus nyata

<RealCase>
Pada Desember 2021, Log4Shell (CVE-2021-44228) memperlihatkan harga sebuah default yang tidak aman pada skala ekosistem. Apache Log4j 2 melakukan JNDI lookup pada string yang lewat di pesan log, dan fitur itu aktif secara default: aplikasi apa pun yang mencatat input yang dikendalikan penyerang — username, header, form field — bisa ditipu untuk men-fetch dan mengeksekusi kode dari server remote. Konfigurasi yang rentan bukan kesalahan yang dibuat oleh siapa pun; itu konfigurasi yang diterima oleh semua orang. Tim di seluruh dunia menghabiskan berminggu-minggu untuk patch dan menginventarisasi paparan. Secure by default — lookup mati kecuali diaktifkan secara eksplisit — tidak akan menghilangkan cacat parsing-nya sendiri, tetapi akan mengurangi populasi yang terekspos dari instalasi default di mana-mana menjadi himpunan yang jauh lebih kecil yang dengan sengaja menyalakan fitur itu. Advisory: https://logging.apache.org/log4j/2.x/security.html
</RealCase>

## Tensi dan trade-off

- **Default aman vs. least astonishment**: default paling aman yang tak bisa di-boot siapa pun tidak melindungi apa pun — pilih default terkuat yang masih berfungsi dalam lima menit pertama.
- **Secure by default vs. Hyrum's Law**: begitu sebuah default di-ship, seseorang bergantung padanya; mengubahnya nanti adalah breaking change, maka kenyamanan yang tidak aman yang di-ship hari ini adalah migration paksa esok hari.
- **Hardening vs. YAGNI**: default yang dirawani untuk threat model imajiner menjadi labirin konfigurasi yang dilewati user lewat jalan memutar — hardening-lah untuk ancaman yang benar-benar dihadapi produk itu.

## Prinsip terkait

- [Fail-Safe Defaults](/id/docs/principles/security/fail-safe-defaults) — saudara di sisi access control: tolak kecuali diberikan.
- [Defense in Depth](/id/docs/principles/security/defense-in-depth) — default adalah lapisan pertama, tidak pernah satu-satunya.
- [Least Astonishment](/id/docs/principles/design/least-astonishment) — default yang aman pun harus tetap masuk akal bagi siapa pun yang menemukannya.
- [Explicit Contracts](/id/docs/principles/api/explicit-contracts) — switch opt-in dengan nama jelas dan blast radius yang terdokumentasi.
- [Hyrum's Law](/id/docs/principles/api/hyrum-law) — mengapa mengubah default yang sudah di-ship adalah breaking change.
