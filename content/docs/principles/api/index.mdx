---
title: API
description: Contracts across boundaries — explicit, versioned, and honest about what users will actually depend on.
---

An API is a promise made to strangers. The principles in this category are about keeping promises honest: say exactly what you mean, change meanings only through versions, and accept that once enough people depend on you, even your accidents become contracts.

<Cards>
  <Card title="Explicit Contracts" description="Everything crossing a boundary carries an explicit, validated contract — implicit assumptions rot silently until they fail at 3 a.m." href="/docs/principles/api/explicit-contracts" />
  <Card title="Versioned Contracts" description="Public contracts change only through versions with deprecation windows — never mutate the meaning of an existing one." href="/docs/principles/api/versioned-contracts" />
  <Card title="Hyrum's Law" description="With enough users, every observable behavior of your system will be depended on by somebody — including the ones you never promised." href="/docs/principles/api/hyrum-law" />
  <Card title="Robustness Principle" description="Be conservative in what you send, liberal in what you accept — but write down exactly how liberal, or tolerance becomes unprovable behavior." href="/docs/principles/api/postel-robustness" />
</Cards>
