<AIInstruction>
Perlakukan setiap dependency sebagai kode yang akan berjalan dengan permission yang sama di production. Jangan pernah meng-install package yang belum diperiksa: riwayat maintainer, aktivitas release, install script, jejak transitive. Selalu pin versi persis dan commit lock file; jangan pernah me-resolve version range secara otomatis. Jika sebuah dependency tiba-tiba berganti maintainer atau berubah perilaku, berhenti dan selidiki sebelum upgrade.
</AIInstruction>

<Severity level="important" />

## Definisi

Kode pihak ketiga dieksekusi dengan otoritas pemakainya, di dalam trust boundary-nya, sejak momen ia di-install. Supply chain vetting berarti setiap dependency dipilih secara sengaja — terpelihara, dipahami, minimal — lalu dikunci oleh lock file dan digest sehingga yang di-audit adalah yang dijalankan. Pertanyaannya tidak pernah "apakah package ini berguna", melainkan "apakah package ini, situasi maintainernya, dan semua yang ia tarik masuk, layak dieksekusi dengan credentials ini".

## Kapan pakai

- Menambahkan dependency baru apa pun, langsung maupun transitive, ke codebase production.
- Image CI dan build — tempat kode orang asing berjalan sementara secrets ikut hadir.
- Base image, action, plugin, dan CLI yang di-install ke dalam pipeline.
- Maintenance terjadwal: me-review daftar dependency yang sudah dimiliki.

## Kapan TIDAK pakai

- Prototype berbatas waktu yang tak pernah menyentuh state atau credentials production — dihapus atau di-vet sebelum dipromosikan.
- Ketika vendoring utility kecil yang dibekukan (baca, audit, salin, pin) lebih murah daripada hubungan kepercayaan berkelanjutan untuk bergantung padanya.
- Package internal first-party di mana vetting digantikan oleh kepemilikan — tim sendirilah maintainer yang dipercaya.

## Anti-pattern

- Meng-install package pertama yang namanya cocok dengan pesan error.
- Version range di manifest, sehingga clean build berikutnya diam-diam me-resolve kode yang berbeda dari sebelumnya.
- Mem-pipe install script dari README proyek langsung ke CI.
- Lock file berisi ratusan package yang tak dipilih siapa pun dan tak bisa disebut namanya.
- Memakai jumlah unduhan dan bintang sebagai proksi kesehatan maintenance dan kesinambungan maintainer.

## Contoh kode

Salah — range mengambang, install buta:

```bash
npm install some-utils@^1.0.0       # sebuah range, bukan pin
# Build berikutnya me-resolve apa pun 1.x saat itu: tanpa review, mungkin
# dipublish oleh orang baru. CI kini wahana hiburan, bukan pipeline.
```

Benar — pin, lock, audit:

```bash
# Pin versi persis; lock file adalah contract dependency yang sesungguhnya
npm install --save-exact some-utils@1.3.0
npm ci                      # meng-install HANYA yang tercatat di lock file

# Gagalkan build pada kerentanan yang diketahui di himpunan dependency langsung
npm audit --omit=dev        # gerbang CI, bukan saran
```

## Penegakan teknis

<Enforcement>
Vetting harus menjadi tahap pipeline, bukan momen hero di code review:

- **Lock file sebagai contract**: CI meng-install dengan lock file yang dibekukan — resolution baru adalah kegagalan build, bukan kebiasaan.
- **Diff lock file di review**: setiap perubahan dependency muncul di pull request sebagai catatan eksplisit dan terbaca manusia tentang apa yang berubah dan mengapa.
- **Gerbang kerentanan**: langkah audit yang menggagalkan pipeline pada CVE yang diketahui di himpunan dependency langsung.
- **Kebijakan registry**: allowlist atau proxy internal untuk build; tidak ada install live dari registry publik di dalam image production.
- **Digest pinning untuk image dan action**: rujuk digest, bukan tag — tag bisa berubah, digest tidak.
- **Yang mencegah vs. yang mendeteksi**: lock file dan digest mencegah perubahan kode senyap antar-build; audit dan diff mendeteksi risiko yang sudah diterima — dua-duanya, selalu.
</Enforcement>

## Kasus nyata

<RealCase>
Dua insiden npm memperlihatkan kedua setengah dari risiko ini. Pada Maret 2016, package left-pad — sebelas baris kode — di-unpublish dari npm, dan build di seluruh ekosistem patah dalam hitungan jam: ribuan proyek bergantung pada ketersediaan dan penamaan yang tak pernah dijanjikan siapa pun kepada mereka. https://www.theregister.com/2016/03/23/npm_left_pad_chaos/ Pada November 2018, event-stream memperlihatkan setengah yang lain: maintainer lama menyerahkan package itu kepada orang asing, maintainer baru menambahkan dependency berbahaya yang terarah dan mencuri credentials wallet dari user satu produk tertentu, dan versi yang tampak sah itu lolos tanpa perhatian melalui ribuan install. https://github.com/dominictarr/event-stream/issues/116 Pinning tidak akan menghentikan kedua peristiwa itu, tetapi akan mengurangi kerusakannya: unpublish menjadi error build atas pembekuan yang sengaja dipilih, dan versi berbahaya menuntut upgrade yang disengaja dan di-review alih-alih datang sendiri di clean build berikutnya.
</RealCase>

## Tensi dan trade-off

- **Vetting vs. KISS**: setiap gerbang memperlambat loop "tinggal install" yang membuat package manager terasa indah — tetapkan bar berdasarkan blast radius dependency, bukan seremoni seragam.
- **Pinning vs. tetap ter-patch**: dependency yang dibekukan tidak menerima perbaikan dengan sendirinya; pasangkan pinning dengan ritme upgrade terjadwal yang di-review, dan buat upgrade security yang terlewat gagal secara keras di CI alih-alih senyap di production.
- **Meminimalkan dependency vs. DRY tension**: DRY mendorong ekstraksi dan berbagi kode, tetapi setiap package bersama adalah hubungan maintainer yang diwarisi — berbagi punya biaya supply-chain.

## Prinsip terkait

- [Least Authority](/id/docs/principles/security/least-authority) — credentials CI di-scope agar dependency yang compromised tidak bisa menandatangani release.
- [Secrets Hygiene](/id/docs/principles/security/secrets-hygiene) — token yang benar-benar diburu oleh package yang compromised.
- [Blast Radius](/id/docs/principles/reliability/blast-radius) — apa saja yang benar-benar bisa dijangkau dependency yang meledak.
- [Fail Visible](/id/docs/principles/reliability/fail-visible) — drift lock file dan temuan audit harus terdengar keras.
- [DRY Tension](/id/docs/principles/design/dry-tension) — kapan berbagi kode berhenti menjadi gratis.
